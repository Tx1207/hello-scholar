# Manage Specs

保存一份让后来读者理解具体改什么、为什么这样选以及如何判断结果的设计。讲清目标、决定、约束和后果之间的关系；仅列出计划做的动作并不充分。

持续项目设计或实施中，方案的目的和具体做法已经清楚、可以审阅时，就保存为 draft，包含重要未决问题，不等全部选择解决。纯解释、独立质询、明确不保存的讨论或只读请求留在对话中。不要求先使用 `grilling`。

## 选择归属

从已知设计路径和相关项目事实入手；归属不明时使用 Index 或定向搜索。完整读取可能的归属文档，并检查相关 Architecture、代码、测试和证据。沿用项目已经确立的设计归属，不创建竞争的 Spec。使用 hello-scholar Spec 时选择事实支持的最简单分支：

- **修订**：已有一个 Spec 负责相同能力和生命周期。
- **新建**：能力具有独立价值、验收边界和生命周期。
- **替代**：目标设计将取代已经采用的契约或实现模型。

根据决定的职责和生命周期选择，不按改动文件数量选择。小修复也可能需要更新已有契约，大型局部重构也可能无需新 Spec。证据明确时直接确定归属；只有同样合理的归属或尚未确定的用户选择会实质改变设计时，才询问一个聚焦问题。创建新身份时读取 [assets/spec-identity.zh_CN.md](assets/spec-identity.zh_CN.md)。

## 连贯解释设计

先说明当前推荐或已接受的决定、改变的对象与行为，以及决定性理由。把问题连接到具体设计：谁负责决定和状态，数据与控制如何流动，调用方看到什么，失败意味着什么。写出必要实施顺序，以及每个有意义步骤对应的检查。用真正影响选择的取舍解释重要备选，不为填满章节而罗列方案。

区分已确认事实、假设、已接受决定和未决选择。说明做法的哪一部分依赖某个不确定性，以及什么能解决它。修订时保留仍有效的约束，不把完整设计替换为补丁说明，也不静默把建议改成要求。

科研设计中，将问题连接到能够改变下一步选择的比较。说明对照与干预、数据和评价口径、相关控制或相互作用、重复策略、解释规则、预算和停止条件。探索问题不必伪装成成熟假设。一个科研增量可以包含多次 Run；总体设计与跨 Run 结论保存在这里，并链接实际执行。

从用户目标、已确认业务规则和真实外部契约推导可观察验收。代码与测试是证据，不能代替未知规则。关键行为明确用户或调用方实际使用的入口和必需结果。科研区分有效完成调查与满足候选方案采用条件：负结果可以回答问题，同时仍不支持采用。

在稳定 `AC-NN` 旁记录当前证据和限制。Spec 正文本身应讲明重要发现，再链接支持它的代码、检查、审查或 Run。引用帮助读者核对推理，不让读者自行重建推理。

## 维护身份与当前含义

使用 `schema: 1` 和 canonical 路径：

```text
hello-scholar/specs/<topic>/SPEC-NNN-<name>/spec.md
```

尚未确定的设计使用 `draft`。用户接受当前修订，或明确要求按该修订实施时，在解决关键未决选择后设为 `accepted`。实施进度不增加新状态：保持 `accepted`，并在每个稳定 `AC-NN` 旁记录当前证据。只有当前 Revision 的全部验收要求都有当前有效的证据时才设为 `completed`。

范围、行为、接口、约束或判断标准变化时，递增 `revision`，同步更新受影响的设计与验收。重新判断前提已变化的证据和审查结论；无关证据在其实际覆盖范围内继续有效。仅补充证据、格式、日期或生命周期不增加 Revision。后来的 Spec 修订不能改写过去 Run 的实验条件或所用修订。

替代设计先在 draft 中说明拟替代对象，不提前使现有 Spec 失效。只有 successor 已实现、获采用并完成验证后，才写入双方 `supersedes` / `superseded_by` 并将 predecessor 设为 `superseded`。

新中文 Spec 使用 [assets/spec-template.zh_CN.md](assets/spec-template.zh_CN.md)，英文使用 [assets/spec-template.md](assets/spec-template.md)。优先采用指定语言，否则沿用目标项目或已有 Spec 的语言。围绕读者需要理解的决定组织内容，合并不适用的模板分节，并保留已确立的外部使用方契约。现有 Spec 不因模板更新而整体重排。

## 完成

读回变更的设计，查找矛盾、遗漏的决定后果及缺少依据的完成声明。在当前授权范围内使用可用文档检查。只有 CLI 可用且生成 Index 的写入已获授权时才运行 `hello-scholar docs sync`；否则报告跳过的维护，不阻塞 Spec。不创建 `plan.md` 或 `tasks.md`。

交付当前选择、具体变化、Revision 与状态、关键证据，以及仍阻塞工作的决定。Spec 维护本身不执行实现；原任务包含实现时，主 Agent 在已有授权内继续任务，再把后续设计变化和证据带回其归属文档。
