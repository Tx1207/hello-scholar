Skill 的作用是从随机系统中提炼确定性。根本美德是**Predictability（可预测性）**——每次运行中 Agent 采取相同的**过程**，而不是产生相同的输出；下面每个杠杆都服务于它。

加粗术语在 [`GLOSSARY.zh_CN.md`](GLOSSARY.zh_CN.md) 中定义；需要完整含义时查阅该文件。

## 调用

两种选择，付出的成本不同：

- **模型调用 Skill（model-invoked）**保留**描述（description）**，Agent 可以自主触发它，其他 Skill 也可以调用它（你仍然可以手动输入它的名称）。它会增加**上下文负载（context load）**：描述会在每轮都占据上下文。机制：省略 `disable-model-invocation`，并写出面向模型、包含丰富触发条件的描述，例如“当用户想要……、提到……时使用”。
- **用户调用 Skill（user-invoked）**将描述从 Agent 可见范围中移除：只有你手动输入名称才能调用，其他 Skill 也无法调用。它没有上下文负载，但会增加**认知负载（cognitive load）**：你必须记得它的存在。机制：设置 `disable-model-invocation: true`；`description` 变为面向人的一行摘要，移除触发条件列表。

只有 Agent 必须自行调用该 Skill，或其他 Skill 必须调用它时，才选择模型调用。若它始终只会被手动调用，就让它成为用户调用 Skill，避免上下文负载。

当用户调用 Skill 多到难以记住时，累积的认知负载可由**路由 Skill（router skill）**解决：一个用户调用 Skill，列出其他 Skill 及其适用时机。

## 编写描述

模型调用 Skill 的**描述（description）**承担两项工作：说明 Skill 是什么，并列出应触发它的**分支（branches）**。每个词都会增加上下文负载，因此描述比正文更需要严格删减：

- **将 Skill 的主导词（leading word）前置**——描述在这里承担调用职责。
- **每个分支只保留一个触发条件。**为同一分支换词的同义表达属于**重复（duplication）**——“用 TDD 开发功能……用户要求测试优先开发”只是同一分支写了两次。合并它们；只保留真正不同的分支。
- **删去正文已有的身份说明。**描述只保留触发条件，以及“供其他 Skill 使用时……”之类的调用范围说明。

## 信息层级

Skill 由两类内容构成——**步骤（steps）**与**参考（reference）**——它们可以自由组合：一个 Skill 可以全是步骤、全是参考，或同时包含二者。核心决定是使用什么，以及各部分在**信息层级（information hierarchy）**中的位置；这是一条按照 Agent 多快需要该材料排序的阶梯：

1. **Skill 内步骤**——`SKILL.md` 中有顺序的行动，是最高层：Agent 按顺序做什么。每一步都以**完成标准（completion criterion）**结束，即表明工作完成的条件。它必须**可检查**（Agent 能否区分已完成与未完成？）；重要时还必须**穷尽**（如“每个已修改模型都已说明”，而不是“给出改动列表”）——模糊标准会招致**过早完成（premature completion）**。
2. **Skill 内参考**——位于 `SKILL.md`、按需查阅的定义、规则或事实。它常常是合理的平级集合（例如一份审阅中的每条规则处于同一层）——这是有效安排，不是异味。*本 Skill 全是参考。*
3. **外部参考**——从 `SKILL.md` 移到单独文件、通过**上下文指针（context pointer）**访问的参考内容；只有指针触发时才加载。（它涵盖**已披露（disclosed）**的参考——如 `GLOSSARY.zh_CN.md` 这类仍属于 Skill 的同级文件——也涵盖位于 Skill 系统外、任何 Skill 都可指向的完全**外部参考（external reference）**。）

高要求的完成标准会驱动充分的**预备工作（legwork）**——Agent 在工作中进行的查找与探究。无论 Skill 有无步骤都是如此，因为“应用每条规则”与“完成每一步”一样，都能约束扁平的参考内容。

下沉得太少会让顶部臃肿；下沉得太多会隐藏 Agent 实际需要的材料。这种张力就是全部决策。

**渐进披露（progressive disclosure）**是沿阶梯向下移动：将内容从 `SKILL.md` 移到链接文件，让顶部保持清晰。机制：在 Skill 文件夹中放置一个按内容命名的链接 `.md` 文件（本 Skill 将完整定义披露给 `GLOSSARY.zh_CN.md`）。有些 Skill 有多种使用方式，每一种不同方式就是一个**分支（branch）**——不同运行沿 Skill 采取不同路径。分支是最清晰的披露测试：每个分支都需要的内容内联，只有部分分支需要的内容放在指针之后。**上下文指针（context pointer）**的措辞而非其目标，决定 Agent 何时、以及多可靠地访问材料。

阶梯决定一项内容应下沉到多深，**共置（co-location）**决定下沉后哪些内容应放在一起：把一个概念的定义、规则和注意事项放在同一标题下，而不是分散各处，让读到一部分时能同时看到相邻部分。

## 何时拆分

**粒度（granularity）**是划分 Skill 的精细程度，每次切分都会消耗两种负载之一，因此只有切分值得时才拆。两种切分：

- **按调用拆分**——当存在一个应独立触发的明确**主导词（leading word）**，或另一个 Skill 必须调用它时，拆出一个**模型调用 Skill（model-invoked）**。新 Skill 的始终加载的描述会带来上下文负载，因此这种独立可达性必须值得付出成本。
- **按序列拆分**——当后续**步骤（steps）**（即某一步的**完成后步骤（post-completion steps）**）会诱使 Agent 草率完成当前步骤时，拆分该步骤序列。让后续步骤不在视野中，会鼓励 Agent 对当前任务做更多**预备工作（legwork）**。

## 删减

让每个语义只有一个**单一事实来源（single source of truth）**：一个权威位置，使行为变更只需编辑一处。

逐行检查**相关性（relevance）**：它是否仍与 Skill 的工作有关？

接着逐句寻找**无效指令（no-ops）**，而不只是逐行检查：单独对每句话进行无效指令测试；若一句不通过，删除整句而非只是缩短它。要果断——大多数不通过的文字应被删除，而不是改写。

## 主导词

**主导词（leading word）**是模型预训练中已有的紧凑概念，Agent 在运行 Skill 时会围绕它思考（例如 *lesson*、*fog of war*、*tracer bullets*）。它会在全文中重复出现（不必每次都出现——强主导词可能只需一次），逐渐积累分布式定义，并以最少 token 锚定一整片行为区域，因为它能借用已有先验。

它以两种方式服务可预测性。在正文中，它锚定**执行（execution）**：每次这个词出现时，Agent 都会采用同一种行为。在描述中，它锚定**调用（invocation）**：当同一个词也出现在你的提示、文档和代码中时，Agent 会将这种共享语言与 Skill 联系起来，从而更可靠地触发它。

寻找机会，用主导词重构 Skill。一个三元概念在三处完整写出是**重复（duplication）**；描述中用整句指向一个概念——这些都是应当**折叠（collapse）**为单一 token 的段落。示例：

- “快速、确定、低开销” -> *tight* ——将一个阶段中反复表述的同一质量折叠为一个预训练词（一个 *tight* 循环）。
- “你相信的循环” -> *red* ——将模糊闸门变成二元可观察状态（循环在 Bug 上变为 *red*，或没有）。

你同时获得两项收益：更少 token，以及更清晰的思维挂钩。假定每个 Skill 都携带可由主导词淘汰的重复表述——去找到它们。

## 失败模式

当用户正在遇到 Skill 问题时，用以下模式诊断。

- **过早完成（premature completion）**——在一步真正完成前结束它，注意力滑向“完成了”。防御顺序如下：先明确完成标准（便宜、局部）；只有标准无法进一步明确且确实观察到草率推进时，才通过拆分隐藏完成后步骤（按序列切分）。
- **重复（duplication）**——同一语义出现在多个位置。它增加维护与 token 成本，并将该语义在层级中的显著性抬高到超出其真实等级。
- **沉积（sediment）**——因添加看似安全、删除看似有风险而不断堆积的陈旧层。没有删减纪律的 Skill 的默认归宿。
- **蔓延（sprawl）**——即使每一行都仍然有效、独特，Skill 依然过长。它损害可读性和可维护性，并浪费 token。解决方法是信息层级：将**参考（reference）**披露到指针之后，并按**分支（branch）**或序列拆分，让每条路径只携带所需内容。
- **无效指令（no-op）**——模型默认已经会遵守的一行文字，因此你付出负载却没有表达新约束。测试：它相对于默认行为是否改变了行为？弱主导词（模型本已差不多会充分做事时说“be thorough”）是无效指令；修复方式是使用更强的词（*relentless*），而不是换一种技术。
- **否定（negation）**——通过禁止来引导会适得其反：*不要想大象* 会让大象更容易出现，而不是更难。提示**正向目标**：表达期望行为，让被禁止的行为根本不被提及；只有无法正向表达的硬性护栏才保留禁止，即使如此也要配上应采取的行动。
