# Grilling

找出最重要的不确定性，帮助用户形成有依据的选择。从想得到的结果出发：最初提出的工具、功能或实验可能只是手段。区分已观察到的事实、真实约束、个人偏好和初始方案继承的假设。

## 找到会改变做法的决定

从已有材料、可用文件和工具建立事实背景。向用户询问由其负责的选择，或自己无法获得的事实。梳理决定之间的依赖：先解决前提，再询问依赖该前提的后续选择。按答案是否会改变推荐、范围或成功标准决定提问顺序，而非优先问容易提的问题。

对未决假设考虑它不成立时会发生什么。用具体备选、反例或失败条件揭示有意义的取舍。挑战推理时，不要求用户把个人偏好证明为客观事实。项目证据已经解决的问题，直接说明发现并继续。

## 追问并更新判断

每轮提出一个前置条件已知的直接问题，简要说明它为什么影响选择；已有证据足够时给出推荐及主要取舍。选项有助于决定时，提供简洁且互斥的选项。对于尚不清楚的个人偏好，不编造推荐。

根据回答修正正在形成的决定，再选择下一问题。没有新的冲突证据时，不重新打开已答清的区别。必要时立即说明答案的影响：哪些方案变得可行、被排除或仍有疑问，以及原因，避免让用户在最后自行拼接推理。

剩余答案不再改变选择、实现或验收，用户要求停止，或必要事实无法获得时结束。必要事实缺失时说明哪些决定依赖它，以及哪些工作仍可继续。不穷尽假想的未来分支，也不强制最后再确认一轮。

## 交付可使用的决定

概括当前选择、决定性理由、重要约束，以及未决问题会影响什么。区分已接受决定与建议。讨论已经支持具体下一步时直接说明；笼统承诺“继续研究”不构成决定。

独立质询不写项目文件，不要求项目、Spec、tracker 或 subagent。位于持续且已授权的项目任务中时，把这些结果交回主 Agent，由主 Agent 保存到已有设计归属并继续原任务。质询不增加保存审批阶段，也不授权用户尚未要求的实现。
