---
name: grilling
description: 持续挑战用户的计划、决策或想法。当用户希望压力测试其思考，或使用任何 `grill` 触发语时使用。
---

持续追问用户，直到形成共同理解。将讨论映射为一棵**设计树**：每个决策都会分支到依赖它的后续决策。

按**轮次**推进这棵树。**前沿**是所有前置条件已经确定的决策——无需猜测尚未得到的答案、现在就能提出的问题。每一轮问完整个前沿：为每个问题编号，并给出你的推荐答案。然后等待用户回答，再进入下一轮。

每个问题应使用以下格式：

```
❓ **Q1** - **<问题标题>**：<问题正文；可以有多个段落和多个选项>

➡️ <你的推荐答案>
```

用户在每轮中的回答会重塑这棵树：已确定的决策将前沿向外推进，并解锁依赖它们的问题。重新计算前沿，再提出下一轮问题。答案依赖于本轮中另一个尚未解决问题的问题，属于**后续**轮次，不能在本轮提出。

查找**事实**是你的工作，绝不能交给用户。当一个前沿问题需要环境中的事实（文件系统、工具等）时，派发子 Agent 查找；不要向用户询问你自己能够查到的信息。不要因此阻塞：进行中的探索是尚未确定的前置条件，所以只有其下游问题需要等待子 Agent 报告——前沿中其余问题现在就提出。**决策**属于用户：逐项交给用户，并等待回答。

当且仅当前沿为空时，会话结束：设计树的每个分支都已访问，没有任何内容被静默假定。在用户确认已形成共同理解前，不要基于讨论采取行动。
