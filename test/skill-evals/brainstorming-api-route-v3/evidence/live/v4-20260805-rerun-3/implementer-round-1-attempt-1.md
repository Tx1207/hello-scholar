你补充确认了：批量上限固定为 100；导出服务必须一次同步请求返回逐项结果；单项失败不能影响成功项；调用方需要支持按项重试；本轮不需要异步进度查询。

三种方案比较：

1. **全批次成败（all-or-nothing）**
   - 一次请求最多 100 项，任一项失败则整批失败。
   - 不符合“成功项不能丢失”和“按项重试”，会迫使调用方重复成功项。

2. **同步逐项结果（推荐）**
   - 一次请求最多 100 项，响应为每项独立的成功、缺失或失败结果。
   - 成功项保留，失败或缺失项带稳定的逐项标识和可重试信息。
   - 最符合当前约束；调用方可以只重试失败项，不需要异步任务或进度查询。

3. **异步批处理加进度查询**
   - 请求创建任务，之后通过任务状态或进度接口获取结果。
   - 能处理长耗时批次，但与“导出服务一次请求拿到逐项结果”以及“本轮不需要异步进度查询”冲突，增加了不必要的任务生命周期和接口。

推荐采用：**同步逐项结果，单次最多 100 项，部分成功，按项重试**。响应应保持输入项与结果项的可对应关系，并区分成功、缺失和失败；本轮不引入异步任务或进度接口。
