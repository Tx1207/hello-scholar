现有事实：

- `src/retrieval-service.js` 目前只有单文档 `getDocument(id)`，找不到时返回 `null`。
- `clients/export-client.js` 在客户端逐个调用单文档接口，并保留每个输入 ID 的结果；当前客户端承担逐 ID 重试边界。
- 现有接口测试只覆盖单文档查询，以及输入 ID 与结果一一对应的客户端聚合。
- Architecture 明确记载：目前不存在批量契约；`SPEC-007` 只负责副本读一致性，不负责批量响应或部分失败；`SPEC-013` 只负责请求预算，不定义单次/批量响应契约。
- 因此，同步批量入口、异步作业、客户端继续聚合都会引入新的公共接口、失败语义和生命周期边界，不能视为单接口的内部优化。

在比较三种方向前，需要确认一个范围决定：

**是否批准把“导出批量能力”作为具有独立生命周期、接口契约、部分失败语义和验收标准的全新能力来设计，并在后续单独创建 Spec，而不是扩展现有单文档查询的 Spec 或仅修改客户端实现？**
