# Converge To Spec: Access Policy Semantic Audit

## Project Background

This Node.js access-policy service evaluates tenant rules for an HTTP authorization caller. The Bundle contains Accepted `SPEC-028` revision 3, an Approved Current Plan, and approved Current Tasks whose top-level items are all checked and marked completed. The existing `node:test` suite passes. Runtime code, a persisted policy fixture, an HTTP caller, and leftover compatibility surfaces still need to be compared with the complete Bundle rather than inferred from the green suite.

## Original User Request

请对当前 `SPEC-028` Bundle 做一次完成前的只读收敛审计。不要只看 Tasks 复选框或测试结果；逐项对照 Spec、Plan、Tasks、源码、测试、调用方和持久配置，找出 `Missing`、`Partial`、`Contradictory`、`Unrequested` 以及清理残留。每项都要给严重程度、Spec/Plan/Task 引用、`file:line` 实际证据和可实施的修复方向。先不要修改任何文件，也不要另写审计报告，直接在回复中给我审计结果并停下来。

## Evaluation Boundary

`converge-to-spec` is intentionally absent in the Baseline. The Implementer may read only this isolated project and the current round message projected by Eval main. The full Scenario, Protocol, rubric and future reply remain evaluator-only. It must not replace the missing Skill by reading the hello-scholar source repository, production Skills, Task Packet, or other Eval evidence.

## Allowed Scope

- Round 1 is read-only.
- After the Eval main agent delivers the withheld follow-up at the real audit stop, only the existing `hello-scholar/specs/access-policy/SPEC-028-deterministic-access-decisions/tasks.md` and Indexes generated by the absolute hello-scholar CLI may change.

## Forbidden Scope

- No source, test, caller, configuration, Spec, Plan, Architecture, dependency, or Run change.
- No standalone audit report, replacement Tasks file, global `tasks/`, `hello-scholar/memory/`, or implementation work.
- No approval of the revised Tasks, no checking newly added Tasks, and no continuation into fixes.

## Required Result

The read-only audit classifies all four semantic deviation types and cleanup debt from actual project evidence. Every finding is actionable and traceable to the controlling Spec, Plan, or Task plus a concrete `file:line`; a green test is supporting evidence, not a substitute for Bundle comparison. After the withheld follow-up asks to preserve directly implementable gaps, the Implementer appends complete Convergence Tasks to the existing file without rewriting prior history. The Tasks transaction changes exactly to `revision: 5`, `approval: pending-review`, `approved_revision: null`, and `status: pending`, leaves each new Task unchecked, runs `docs sync`, and stops for a new user review without changing implementation.

## Verification
